## Known issues / deviations
- **phosphor_flutter 2.1.0 is incompatible with Flutter 3.47** (`IconData` is `final`, cannot be extended). Switched to `lucide_icons_flutter ^3.1.25` (explicitly allowed by PROMPT.md). Vector icons only; no emoji anywhere.
- `linearToGray` LUT is indexed by linear level quantised to /255, so it cannot be a perfect byte inverse; round-trip tested in linear space (≤1.5/255) and via the exact float pair.
- **Braille glyphs (U+2800–U+28FF) are missing from all three bundled monospace fonts**; the Mode B panel warns when <50% of a set's characters are unsupported, and the sample tool skips such sets. Consider bundling a braille-capable mono font in a later phase if desired.
- Flutter test harness limitation (documented, worked around in tests): a long single `Isolate.run` poll inside `tester.runAsync` never resolves, because the isolate's completion is delivered to the fake-async zone and only runs while the tree is pumped — `_waitFor` in `test/create_flow_test.dart` interleaves short real waits with pumps.
- Create-flow permission UX relies on plugin exceptions + a retry path rather than `permission_handler` (not added; camera/gallery plugins surface their own errors).
- **Phases 0–6 were never run on a device** (Codespaces has none), so 407 green tests still let a launch-blocking defect ship: `MainActivity` sat in package `com.sketchglyph.sketchglyph` while the manifest/namespace resolve `.MainActivity` to `com.sketchglyph.app`, crashing every start with `ClassNotFoundException`. Fixed in `60367d4`, verified by launching on a TECNO KN3 (720x1600 / 280dpi, Android 15). Every phase now ends with install → launch → screenshot, not just a green APK build.
- **Onboarding overflows in landscape** ("BOTTOM OVERFLOWED BY 23 PIXELS" at 1600x720; the column needs more height than landscape offers). Harmless-looking in release (content just clips). Unresolved product decision: lock the activity to `portrait`, or make the onboarding column scrollable/responsive in Phase 8.
- Windows local builds need `kotlin.incremental=false` + `kotlin.compiler.execution.strategy=in-process` in the *user-level* `~/.gradle/gradle.properties`; Defender/indexer file-locking makes Kotlin's daemon fail to close its incremental `.tab` caches, which errors four plugin modules with no real compile failure. Kept out of the repo so Linux CI keeps incremental compilation.
